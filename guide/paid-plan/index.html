1. Gumletの概要と有料プランの強み

本ガイドは、Webサイトの表示高速化（画像最適化）およびセキュアな動画配信（HLS・DRM）を目的としてGumletの有料プランを導入・運用する日本のWeb担当者およびエンジニア向けの実践ガイドです。

Gumlet は、画像最適化（Image CDN）と動画ホスティング・配信（Video Hosting & Streaming）をワンストップで提供するクラウドサービスです。オリジンサーバー（WebサーバーやS3など）のURLやパスを保持したまま、URLパラメータベースのリアルタイム変換とグローバルCDN配信を実現します。

1.1 無料枠（Free）と有料プランの主な違い

Gumletは「Image CDN」と「Video Hosting & Streaming」でプラン体系が分かれており、無料枠でも検証は可能ですが、商用サイトや会員向けサービスでは有料プランへの移行が不可欠です（最新の詳細は Gumlet Pricing ↗ を参照）。

2. 画像最適化（Image CDN）の初期セットアップ

2.1 Sources設定手順

Gumletでは、元の画像を保持しているサーバーやクラウドストレージを [Source]（ソース）として登録します。

GUMLET DASHBOARDSource setup
[Gumlet Dashboard]
   │
   ├─► [Image CDN]（画像CDN）
   │     └─► [Sources]（ソース一覧）
   │           └─► [Add Source]（ソース追加）

パターンA: Web Folder（既存のWebサーバー / WordPress等のHTTP公開元）

  1. 左側メニューから [Image CDN] > [Sources] を選択し、[Add Source] をクリックします。
  2. [Source Type]: [Web Folder] を選択します。
  3. [Base URL]: 既存サイトの画像配置ディレクトリのURLを入力します（例: https://example.com/wp-content/uploads/ または https://example.com/）。
  4. [Subdomain]: 任意の名称を入力します（例: mybrand と設定した場合、https://mybrand.gumlet.io/ が払い出されます）。
  5. [Save Source] をクリックします。

パターンB: Amazon S3（非公開S3バケット連携）

  1. [Source Type] で [Amazon S3] を選択します。
  2. [S3 Bucket Name]: 対象のバケット名を入力します。
  3. [S3 Bucket Region]: ap-northeast-1（東京）などを選択します。
  4. [Access Keys] / [IAM Role]: 推奨はIAMロールによるクロスアカウントアクセス許可、または最小権限（s3:GetObject のみ）を付与したIAMユーザーの [Access Key ID] と [Secret Access Key] を入力します。
  5. [Test Connection] を実行し、接続成功を確認したら保存します。

2.2 カスタムドメイン（CNAME）設定と自動SSL

有料プラン（Growth以上）では、Gumlet既定の https://xxx.gumlet.io ではなく、自社ドメイン（例: images.example.com）で配信可能です。

設定手順:

  1. Gumlet管理画面で作成したSourceの詳細を開き、[Source Settings] > [Custom Domain] を開きます。
  2. [Domain Name] に利用したいFQDNを入力します（例: images.example.com）。
  3. 自社DNSサービス（Cloudflare、Route 53、お名前.com等）で以下のレコードを追加します。
    • Type: CNAME
    • Name: images
    • Target / Value: 払い出されたGumletサブドメイン（例: mybrand.gumlet.io）
    • TTL: 300 または Automatic（※Cloudflareを使用している場合は初期検証時はプロキシを「DNS Only（灰色雲）」に設定）
  4. Gumlet管理画面に戻り、[Verify DNS] をクリックします。
  5. 検証完了後、Let's Encrypt等によるSSL/TLS証明書が自動発行され、数分〜15分程度でHTTPS通信が有効化されます。

3. WordPress・既存サイトでの導入と実装

WordPressでは、Gumletプラグインを使用するか、テーマの画像URLをGumletの配信URLへ切り替えます。まずは既存画像URLを保持したまま、検証対象のページで表示・LCP・転送量を確認します。

Web Folder連携

WordPressの uploads ディレクトリをSourceとして登録し、既存のオリジンを維持したまま配信URLを組み立てます。

srcsetの検証

表示幅ごとのURLとsizes属性を確認し、端末に対して過大な画像を配信しないようにします。

公開後の計測

実装前後でLCP、画像転送量、キャッシュヒット、表示崩れを同一条件で確認します。

4. 動画配信・DRMの初期設定

Video Hosting & Streamingでは、動画のアップロードからHLS配信、埋め込みプレイヤー、アクセス制御までを管理します。会員向けや研修用途では、ドメイン制限、リファラー制限、DRM、動的ウォーターマークの必要性を用途別に確認します。

  • 動画の公開範囲と、許可する再生ドメインを整理する
  • DRM Protection、MP4 Download、ウォーターマークの条件をプランと合わせて確認する
  • 埋め込み後にスマートフォンを含む実環境で再生・シーク・アクセス制御を確認する

5. コスト抑制と継続運用のポイント

有料プランでは、月間転送量、動画ストレージ分数、超過料金、必要な保護オプションを分けて見積もります。利用量を定期的に確認し、プラン変更・画像品質・配信設定を同じ前提で評価することがコスト抑制につながります。
